# 题湖题库数学题分类助手

本项目由 Tampermonkey 脚本和本地分类服务组成，用于在题湖题库页面上采集大题、展示分类建议，并把题目送入既有的中考数学目录体系。

第一版已经提供：

- 本地服务，默认监听 `127.0.0.1:3232`。
- 目录与分类规则配置校验。
- 题目结果 SQLite 缓存。
- 当前页分类缓存的一键清除；清除后下次识别会重新请求云端模型。
- 实时分类作业：浏览器只提交一次本地任务并轮询单一状态接口，已完成题目会立即显示，不依赖浏览器长连接。
- 采纳与全部采纳：建议目录与当前目录一致时，仅在前端确认采纳，不读取属性页或发送移动请求；其余题目才独立提交并回读确认。主面板二次确认会拆分两类数量，并以原生异步并发处理需要移动的题目。
- 人工修正：点击题卡的建议分类，逐级选择题湖已有目录后再采纳；发生实际移动的人工路径独立持久化并保留审计记录。
- 今日工作成果：仅在题湖回读确认一次真实目录移动后写入独立台账；按 UTC+8 的当天范围查询，并按题目展示当天最新移动的 Stable Code 及原、现四层目录路径。
- 今日工作成果导出：一键生成可离线打开、转发或打印为 PDF 的独立 HTML 报告；也可生成适合手机纵向查看的窄版 PNG 长图。
- 页面刷新后自动从本地缓存恢复已有分类建议，并根据题湖当前目录标识“当前目录无需调整”。
- 保守的规则分类器：没有唯一且明确的既有目录时，一律标记为人工复核。
- 油猴脚本的页面采集、右侧折叠面板、当前页批量识别和题卡分类标记。
- 以左侧目录树当前选中的二级或三级目录为“当前目录范围”，通过“导出所有题库”遍历全部分页、异步读取全部可用题目属性并导出本地交接包。导出不调用云端目录模型，也不读取或写入 Excel；后续由用户手动启动 ChatGPT Agent，使用 `math-exam-directory-curation` Skill 生成目录方案。
- 归类结果回填：Skill 在新目录写入后逐题归类，产出的「题号 + E 列知识点编号」清单可在面板上点“导入归类结果”交回本机。导入先预演、确认后才落库，落库结果随即作为该页的分类建议显示，来源标记为“Skill 归类”。

尚未接入模型时，规则分类器不会把模糊题目自动加入组卷篮；这是有意的保护措施。

分类模型固定采用“专题路由 → 专题内分类与全局自检”的两步方案。实时分类先只发送全局专题目录：专题10之前按 Skill 的“最晚必备知识点”定位专题；从专题10“三角形”起及后续专题的 `【大题】`，则按压轴题的最终核心突破口定位专题，不因扇形面积、旋转、坐标或代数运算等辅助步骤而转移。第二轮按实际命中的专题选择三级、四级目录，同时从全量专题复核路由。本地只校验目录结构、编号保护和路由一致性，不对特定数学知识点作硬编码否决。每组完成即写入本地缓存并显示题卡标记。完整调研和选型依据见 [MODEL_INTEGRATION_RESEARCH.md](MODEL_INTEGRATION_RESEARCH.md)。本项目不使用本地模型。

实时模型、批处理 JSONL、批处理提交、结果同步导入和目录候选计数均已实现。未设置云模型密钥时，服务会安全回退到保守的规则分类，绝不会擅自向外发送题目。

## 依赖管理

本子项目使用 `uv` 管理全部 Python 依赖，配置和锁文件位于本目录。首次运行：

```powershell
Set-Location .\wulou-question-curation-assistant
uv sync
```

增加、删除或升级依赖时使用 `uv add`、`uv remove` 和 `uv lock --upgrade-package <包名>`，不要直接使用 `pip install` 修改环境。

## 启用云端分类

1. 启动本地服务。
2. 在油猴面板的“模型方案”中新建并命名方案，例如“GPT”或“DeepSeek”；每套方案分别保存目录分类、专题选择、协议、接口地址和 API 密钥。支持 Responses、Chat Completions 与 Claude Messages；专题选择模型可留空以复用目录分类模型。密钥只写入 Git 忽略的 `settings.local.yaml`，已保存的密钥不会回传或显示在浏览器。
3. 选择方案即可立即切换；方案名称在编辑完成后会立即保存，长按方案卡片可拖动排序，“处理速度”由所有方案共用。模型、接口地址和密钥等其余设置则点击底部“保存设置”后才提交；留空密钥输入框会保留已保存的密钥。
4. 日常处理页面时点击“识别当前页”即可。批处理 JSONL、提交和结果同步能力保留在本地服务中，适合后续一次处理数百题以上的离线任务；为保持面板简洁，默认不在油猴主面板显示。提交动作会在浏览器再次确认，因为它会产生云端费用。

分类逻辑在服务端保持统一，协议适配只发生在请求、结果解析和离线批处理边界。接口地址可直接填写 API 根地址，例如 `https://api.openai.com` 或 `https://api.anthropic.com`；服务会在未包含版本路径时自动补上一次 `/v1`，已填写 `/v1`（或 `/v1beta`）时不会重复添加。目录分类与专题路由的推理强度会分别按所选协议发送；可选值为 `none`、`low`、`medium`、`high`、`xhigh`、`max`，`max` 适合有人工挑选的高精度复核，不建议作为整页默认值。

部分上游网关会按客户端特征实施访问规则。对此不再按供应商域名写死规则：在当前方案的“高级连接选项”中选择“兼容模式”即可应用兼容请求标识；如供应商要求额外标识，可填写自定义请求头。两类设置都只作用于当前方案，并被测试、实时分类和离线批处理共用。

保存前可点击“测试连接”，但它不是必需步骤：未测试时，“目录分类”和“专题选择”可直接输入模型名；测试成功后，返回的模型会自动成为两个原生选择框的选项。测试只请求模型目录 `/models`，不携带模型名称、不发送模型生成请求，也不消耗推理 token。专题选择留空时复用目录分类模型；更改协议、接口地址或密钥后需重新测试以刷新候选模型。测试会先立即返回任务编号，再以短轮询读取结果，避免浏览器中断长连接后遗漏后端结果；设置页只显示“可连接”或“不可连接”，详细诊断仅保留在本机服务日志。`chatgpt.com/backend-api/codex` 属于 ChatGPT/Codex 登录态内部接口，不能作为 API Key 地址使用。Claude Messages 使用 `output_config.format` 取得 JSON Schema 结构化分类结果；不支持的 schema 约束仅在传输层转换，本地仍严格校验。三种协议均支持实时分类和离线批处理：Responses 与 Chat Completions 走 OpenAI Batch；Claude Messages 走原生 Message Batches，并按 `custom_id` 导入可能乱序返回的结果。

每个离线批任务会绑定导出时选中的模型方案；在任务完成前切换其他方案不会改变该任务的提交、同步或导入协议。不要删除仍有待同步任务所绑定的方案。

整页实时分类没有浏览器端硬超时。一分钟是常态性能目标，模型排队或网络波动时作业会继续在本机后台运行；服务端网络失联保护至少为 600 秒，不作为页面分类的业务时限。网关过载、限流（429/5xx）和连接失败会被自动重发，默认共尝试 3 次（首次之外最多重发 2 次），指数退避并叠加随机抖动；读超时不重发——那时请求已经送达上游，重发既可能重复计费，也要让人再干等一个完整超时周期，这类失败会把该批题目标为待人工复核。尝试次数可用 `classifier.pipeline.retry_attempts` 调整（1 到 5）。离线批任务的提交不做重发：批任务没有幂等键，重发会让同一批题目被跑两遍并重复计费。
专题路由和专题内分类每批最多 10 道题，并共享全局云端并发上限。服务端会把固定 Skill 和目录放在动态题目前；支持精确前缀缓存的兼容网关可复用固定上下文。模型调用结束后会持续把完成题目写入缓存，油猴脚本每 2 秒轮询同一个作业状态并立即渲染新结果。
分类缓存以题目内容、目录版本、规则正文哈希、云端提供方协议及模型名为准；题湖当前三级或四级叶子仅用于记录题目所在语境。题目移动到新目录后仍复用同一分类结论，不会因为目录变化再次调用模型；页面会结合当前叶子和本机移动台账显示“已归位”或“已移动”。

三级目录没有四级子目录时，三级本身就是最终分类目录；只有实际存在四级子目录时才要求四级唯一匹配。每次新分类还会保存经过脱敏的模型文本输入快照：题干、答案、可用的备用文本或 LaTeX，以及排版解析警告；不保存页面 DOM、图片 URL、令牌或 API 密钥。该快照仅供本地排查分类异常，不在日常题卡中展示。

## 全量题库导出与目录整理

在题湖页面选中二级或三级目录后，点击“导出所有题库”。脚本会遍历该当前目录范围的全部分页、读取全部可用题目属性，并在 `.local-data/directory-exports/` 新建交接包：

- `题库全集.jsonl`：去重后的完整题目文本；
- `目录整理交接清单.json`：当前目录范围、采集缺口、现有专题二三四级目录树和交接说明。

随后由用户在 ChatGPT 中手动启动 Agent，并使用 `math-exam-directory-curation` Skill 的“目录骨架方案模式”读取交接包，先生成目录方案，不做逐题归属，也不写 Excel。方案获认可后，用户可另行要求进入“目录骨架写入模式”：仅写入当前目录范围的三级、四级目录结构，新增或语义改变目录的 S 列保持空白、等待逐题归属；也可进入“完整写入模式”完成题号清单与实际题量。两种写入模式都会自行匹配 Excel 范围、创建新版本。导出动作本身不读取或修改 Excel。

### 归类结果回填

本机与外部 Skill 之间只有一件事可以对齐：**Excel E 列的知识点编号**。本机目录 ID（形如 `l3-107-0ead8e99f1`）由 Excel 行号推导，插入或删除一行就会整体改变，外部无法预知；E 列编号写在单元格里，双方都读得到。因此 Skill 的逐题归类结论只写“题号 + 知识点编号”，由本机按当前目录版本反查三级、四级目录。**编号是原样照抄回传的**：编号是署名制，本机按 E 列原值等值反查，不校验前缀或命名格式（别人建的编号有自己的写法，详见文末“当前边界”）。

交接清单里的 `import_contract` 字段会写明这段契约，处理方式如下：

1. 新目录写入 Excel 并上传题湖，本机服务在下次读取目录时自动切换到新版本。
2. Skill 再次运行，把每道题分到具体的三级、四级目录，输出下列任一形态的文件：
   - JSON 对象：`{"taxonomy_version": "...", "items": [{"exercise_id": "...", "knowledge_point_id": "..."}]}`
   - JSON 数组，或逐行 JSONL（每行一个 `items` 元素）。
3. 在分类助手面板点击“导入归类结果”，选择该文件。面板先预演并列出可归位题数与编号对不上的条目，确认后才写入本机 SQLite。确认框里的“保留已有手工修正”默认勾选，可随时取消。
4. 写完后本页立即重新读取，题目显示“Skill 归类”建议；点“采纳”时才会按原有逻辑写入题湖。

导入结果与人工修正保存在同一张表，靠 `source` 区分来源，审计语义不混：
- 重新导入时要不要保下已有人工修正，由确认框的勾选项决定，接口上是请求体里的 `"preserve_manual_decisions": true`。判据与读取层完全一致：目标目录在当前目录里还解析得到，就算仍然成立、跳过不覆盖；目标目录已被改名或撤销的，本就作废，不再占位。
- 旧记录是否还算数，看它的目标目录在当前目录里还解析不解析得到：目标目录还在就继续生效，被改名、移位或撤销才需要重新归类。所以改动某个专题的目录，不会牵连目标落在其他专题的人工结论——而不是整份工作簿换个版本号就整批作废。
- 结论仍然成立、但它定稿之后所在专题又调整过目录的，题卡上会多一个“目录已调整 · 建议复核”提示。建议照旧可用、照旧能采纳，只是未必仍是最合适的，要不要重看由人决定。
- 逐条校验不会整批作废：编号对不上的条目会被跳过并在报告里逐条列出原因（编号不存在、重复题号、父三级已编号却落四级等）。

## 安装油猴脚本

1. 在 Tampermonkey 新建脚本。
2. 将 [wulou-question-curation-assistant.user.js](userscript/wulou-question-curation-assistant.user.js) 的完整内容粘贴并保存。
3. 登录题湖题库，进入题目列表页面并刷新。脚本会自动连接本地服务，读取已持久化的云端模型、接口地址和密钥状态。少数兼容接口拒绝标准客户端时，可在方案的“高级连接选项”选择兼容模式，或按供应商文档补充自定义请求头；这些设置随当前方案保存，并同时用于测试、实时分类和离线批处理。
4. 点击页面右侧的“分类”入口。脚本会读取题湖页面标题作为弱提示；云端模型仍会从全部专题中按分阶段规则重新判断：专题10之前看最晚必备知识点，专题10及后续 `【大题】` 看压轴题核心考点；再点击“识别当前页”。

处理三级目录下的大量分页时，使用“识别当前目录全部题目”。它会先读取并固定当前目录范围内全部分页的题目快照，再分类；800 题级当前目录范围作为一个本地总作业持续流水化，服务内部仍以每 10 题为模型微批，并对所有作业共享同一个 1–5 路并发闸门。单个总作业的保护上限为 1000 题，超过时才自动拆分。后续“当前目录全部采纳”始终按该快照处理，不会因题目移出当前目录而跳页或漏题。若结果中有“待复核”，脚本会进入无写入副作用的“审核优先视图”：按题湖原本每页容量，将待复核题连续排在第 1、2… 页，普通建议随后展示。请用该视图的“上一页 / 下一页”逐题修改目录；完成后点击“退出审核优先视图”恢复题湖原始分页。当前页识别同样会把待复核题移到该页最前。一键采纳只处理普通建议，不会批量处理待复核题。题目进入建议目标叶子后，在其他当前目录范围中会显示“已归位”；存在本机移动台账时显示“已移动”，两者都不会再次进入采纳队列或调用模型。

建议分类确认无误后，可点击题卡上的“采纳”；如需处理整页，则在主面板点击“全部采纳（N）”。建议目录与已读取的当前目录一致时，题卡会明确显示“当前目录无需调整”；点击“采纳”只更新前端状态，不读取属性页、不发送题湖移动请求，也不写入工作成果。主面板确认框会拆分“仅本地确认”和“并发提交题湖移动请求”的数量。只有目录不同的题目会替换属性表单中的 `exercise_catalogue_id`，再以 3 路原生异步并发逐题提交和回读确认；单题失败不会中断其余题目，且会保留为待采纳状态。若确实发生目录移动，脚本会将当前页面导航中的原目录名称路径、采纳后的目标名称路径和 Stable Code 追加到本机工作成果台账；三级目录可直接作为叶子，不要求四级。工作成果描述人工操作的目录语境，不使用题目内部目录 ID 反查旧名称。

发现模型建议不正确时，直接点击题卡中的分类路径。选择器会按“专题 → 二级目录 → 三级目录 → 四级目录”逐级展示题湖已有目录；三级目录没有子目录时可直接作为最终路径。选择完成后，题卡会显示“人工修改”；若目标不同，按钮显示“采纳并移动”，并在题湖回读成功后将人工路径保存到 SQLite。它与模型缓存分表存储，并按“题目 ID + 修改前题湖目录叶子 ID”区分语境；每次实际移动都会追加审计记录。目录工作簿更新后，人工修正是否仍生效，看它的目标目录在当前目录里还解析不解析得到：目标目录还在就继续用，被改名、移位或撤销才让 LLM 重新分类。清除本页缓存不会删除人工修正。

右侧面板的“今日工作成果”会显示 UTC+8 当天已分类题目数、原目录涉及的专题，以及每题当天最新一次分类的 Stable Code 和“原专题 / 二级 / 三级 / 四级 → 现专题 / 二级 / 三级 / 四级”。专题只取原目录第一层，忽略现目录，并按“专题”后的数字升序排列。服务端会将 UTC+8 的当天 `00:00:00` 至次日 `00:00:00` 换算为 SQLite 的 UTC 左闭右开查询范围，因此不会混入前一天或次日的数据。同一题当天多次移动时，汇报页只显示当天最新一条；台账仍保留全部审计记录，清除当前页缓存也不会删除这些工作成果记录。点击“导出今日”会下载独立 HTML 报告，可直接分享给他人或在浏览器中打印为 PDF；点击“今日截图”会生成 720px 宽的窄版 PNG 长图，适合手机纵向查看。

如果需要重新判断当前页面的题目，可点击“清除当前页缓存”并确认；操作只删除该页题目在本机的分类缓存，不会影响其他题目、工作成果台账或云端设置。

脚本只读取当前登录权限已经允许访问的题目。加入组卷篮和写入 Excel 不会在当前版本自动执行。

## 当前边界

- 新三级、四级目录只能作为候选提出，必须通过数量、旧目录对照、语义审核和人工确认。
- Excel 写入必须生成新版本，不能覆盖基准工作簿。
- **知识点编号是署名制：谁建的目录谁定编号。** 任何人都可以用自己的“字母+数字”串编号，没有全局统一格式。`ZCSQG<YYYYMMDD>SF<NN>` 是本机主人的署名写法（`SF` 是主人的署名），只在主人自己或替主人干活的 Skill **新发**编号时使用；只有通过审核的新增知识实体才能占用编号。别人建的编号用他们自己的字母加数字即可，同样合法。
- **编号格式不做校验，也不该加校验。** 因为编号是署名制，目录里现存的 E 列编号必然有多种前缀和写法（实测 `ZCSQG`、`ZCSZKH`、`ZCSZKHcwj`、`ZCSQGLQ`、`ZCSQGCYLZ`、`CSZSDCF` 等，同一前缀下日期段和序号段也不统一），这些全是合法编号，不是“不规范”。本机一律按 **E 列原值等值反查**（`taxonomy.resolve_knowledge_point_id`）。`excel_sync.SF_PATTERN` 只服务于给当天新发、署名为 `SF` 的编号查重避号，**不是“某目录是否已有编号”的判据**，别拿它去筛目录。任何新增的格式校验都会让现在能用的合法编号突然失效。

## Excel 目录预检

先只读检查工作簿，不会修改任何文件：

```powershell
uv run --project .\wulou-question-curation-assistant python .\wulou-question-curation-assistant\scripts\preview-excel-update.py <基准工作簿路径> '专题一 实数' --output .\excel-preview.json
```

`server/excel_sync.py` 的写入函数仅接受人工审核为 `approved` 的明确方案，并拒绝覆盖基准或已存在的目标文件；在尚未提供实际基准工作簿前，不会生成正式 Excel 版本。

页面不生成目录方案：三级、四级目录的新增、改名、拆分与合并都由 `math-exam-directory-curation` Skill 产出并经人工审核，页面只负责导出交接包与回填逐题归类结果。若确需让本机脚本按一份已审核的 JSON 方案写 Excel，审核人应补全并确认基准 SHA-256、工作表、`replace_start_row`、`replace_end_row` 和待写入的三级/四级行后，使用下列命令创建新版本：

```powershell
uv run --project .\wulou-question-curation-assistant python .\wulou-question-curation-assistant\scripts\apply-approved-refactor.py <基准工作簿路径> <approved-plan.json> <新版本工作簿路径>
```

该写入器拒绝覆盖基准或已存在的输出文件，并逐单元格比较替换范围前的区域与范围后平移区域；发现范围外数据变化即失败。

首次配置或需要手动校验导出结果时，也可以从确认的目录工作簿导出真实分类目录：

```powershell
uv run --project .\wulou-question-curation-assistant python .\wulou-question-curation-assistant\scripts\export-taxonomy.py <基准工作簿路径> --output .\wulou-question-curation-assistant\.local-data\taxonomy.yaml
```

导出器严格按工作簿列层级读取：A 列是一级专题，B 列是二级目录，C 列是三级目录，D 列是四级目录；`【大题】`固定是二级目录。形如 `12.4 一般角的三角函数值` 的 B 列标题不会被提升为一级专题。N 列中的目录语义会用于模型分类；如历史说明以“证据题目 ID：…”附带题号，导出时会自动剥离到仅供审计的证据字段，绝不传给模型。导出格式版本包含在 `taxonomy_version` 中，解析规则变化会自动使旧分类缓存失效。
