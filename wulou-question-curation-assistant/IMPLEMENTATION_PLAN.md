# AI分类助手实施规划

## 1. 项目目标

项目用于提高“题湖题库”中考数学大题的整理效率。系统从当前登录页面读取题目，将每道题映射到既有的“专题 → 【大题】→ 三级目录 → 四级目录”，在页面题卡旁展示建议分类，并由使用者确认后加入对应组卷篮。

推荐的最终形态由两部分组成：

1. **Tampermonkey 油猴脚本**：读取页面、展示分类、维护 12 个组卷篮映射、提交人工确认后的入篮操作。
2. **本地分类服务**：监听 `127.0.0.1:3232`，完成文本标准化、目录候选约束、模型调用、规则校验和分类缓存。

设计目标：

- 题目采集以网页已有结构化数据为主，避免无必要的整页下载和 OCR。
- 对每道题给出唯一的建议分类、置信度和简短依据。
- 低置信度、跨专题或目录冲突题目必须进入人工复核。
- 12 个组卷篮作为可切换的分类槽位，不与完整分类体系永久绑定。
- 分类结果可以缓存、导入、导出和追溯。
- 未经人工确认，不自动修改网站组卷篮状态。
- 当现有目录确实无法覆盖成组出现的新题型时，生成三级或四级目录候选；通过数量、语义和历史目录审核后，再同步写入新的 Excel 版本。

## 2. 已确认的页面能力

基于 2026-09-09 对题湖题库页面的实际检查：

- 每个题卡元素可以读取稳定的题目 ID，例如 `data-exercise="2529221"`。
- 页面能够提供题目编号、来源、年份、难度、问题图片和答案图片。
- 题卡“属性”入口指向同源接口，例如：

  ```text
  /exercise/getExerciseInfo?id=<exercise_id>&rollPart=0&get_html=1&subject=3
  ```

- 当前抽查页面 30/30 道题均可取得 `question_press` 和 `answer_press`。
- 当前页面的 12 个原生组卷按钮均带有题目 ID 和 `join_type`，可以在人工确认后复用网站原有入篮逻辑。
- 当前抽查中，以 3 个并发请求读取 30 道题属性约需 6.8 秒。

以上结构来自当前版本页面，实施时必须集中封装选择器和接口解析器，并提供结构变化检测，不能把页面细节分散在业务代码中。

## 3. 范围与边界

### 3.1 第一阶段纳入范围

- 当前登录用户有权访问的题湖题库页面。
- 中考数学专题下的 `【大题】`。
- 当前目录和分页中可见的题目。
- 题干文本、答案文本及必要时的题目图片识别。
- 三级、四级目录建议分类。
- 12 个组卷篮的目录映射、页面标记和人工确认。
- 本地缓存、操作记录及 JSON/CSV 导入导出。

### 3.2 暂不纳入范围

- 模型直接创建并立即启用新的三级或四级目录；模型只能生成待审核候选。
- 未经审核的全自动批量入篮。
- 绕过网站登录、权限或访问频率限制。
- 将整套网页保存为离线站点。
- 第一版直接处理小题、选择题和填空题。
- 覆盖或就地修改既有 Excel 分类总表；目录变更只能写入保留历史版本的新文件。

## 4. 分类规则

分类规则以本机现有的 `math-exam-directory-curation` Skill 为权威来源，分类器和人工复核界面必须使用同一份规则快照，避免 Skill、模型提示词、程序校验和人工判断互相冲突。

当前规则来源：

```text
C:\Users\foogl\.codex\skills\math-exam-directory-curation\SKILL.md
C:\Users\foogl\.codex\skills\math-exam-directory-curation\references\classification-and-writing-rules.md
C:\Users\foogl\.codex\skills\math-exam-directory-curation\references\comparison-and-semantic-audit.md
```

实现时不让油猴脚本直接读取 Skill 文件。应把与网页逐题分类有关的规则提取为项目内可执行规则包，并记录来源文件哈希：

```text
Skill 原文
   ↓ 人工审核的规则同步脚本
config/classification-rules.yaml
   ↓
本地分类服务、模型提示词、结果校验器、页面规则说明
```

规则包至少包含 `rule_version`、来源文件、来源哈希、专题顺序规则、三级分类轴、四级分类轴、目录保护规则、强制复核条件和审核清单。Skill 更新后先生成规则差异；审核通过才提升 `rule_version`。旧分类缓存不得无条件沿用。

### 4.1 Skill 规则适用范围

本项目直接采用以下规则：

- 题目以平台 `exercise_id` 为首要稳定身份，题号不能单独作为去重键。
- 先判断完整前置知识和最晚前置专题，再判断当前专题内的三级、四级目录。
- 三级目录以首要对象或情境为分类轴；四级目录以主问或决定性条件为分类轴。
- 目录标题去除单题的地点、物品、行业和人物背景，保留可复用的数学骨架。
- 对全部三级目录执行两两互斥检查，不只比较相邻目录。
- 对同一三级目录下的全部四级目录执行唯一命中检查。
- 父三级目录 E 列已有知识点编号时，默认只允许三级粗分并标记待统一细分。
- 新目录必须有真实题目和稳定检索价值，不为预想题型建立空目录。
- 跨专题题目至少定位到目标专题的现有三级目录；没有可靠四级锚点时标记待目标专题细分。
- 自动程序负责数量、唯一性、目录引用、映射和缓存检查；前置知识、标题语义、分类轴和盲分结果仍须模型或人工复核。

Skill 中关于 Excel 写入、工作表列保护、`SF` 编号分配、历史工作簿版本和文件替换的规则不属于第一版只读采集，但属于完整项目的后续里程碑。把确认结果写回 Excel 时，必须重新进入该 Skill 的 Excel 完整性保护流程，不能由油猴入篮流程代替。

### 4.2 专题定位

1. 提取解题所需的必要知识。
2. 按专题顺序确定这些知识最晚出现的位置。
3. 将题目归到全部必要知识均已具备的最早专题。
4. 如果题目明显依赖当前专题之后的知识，标记为“跨专题复核”，不强行放入当前专题。

### 4.3 三级目录

三级目录回答“这道题主要研究什么对象或场景”。标题应表示可复用的数学对象，删除地区、人名、商品等题目背景。

示例：

```text
实数的应用
实数综合计算
数轴与实数
```

### 4.4 四级目录

四级目录回答“最终要求解决什么问题，或者哪一个条件决定了解法”。

示例：

```text
利用实数运算解决实际问题
含分母有理化的实数计算
数轴上两点距离与实数运算
```

### 4.5 唯一性与目录保护

- 每道题只能有一个最终建议路径。
- 相邻目录必须有互斥的判定条件。
- 正式分类只能输出当前目录版本中真实存在的路径；无法合理覆盖的新题型进入独立候选池，不把候选标题伪装成已生效目录。
- 如果三级目录已绑定知识点 ID，而四级目录尚未统一细分，只归入三级目录，并标记“待该三级目录统一细分四级目录”。
- 不根据预期题型自动创建空目录。
- 无匹配、多匹配、跨专题和低置信度结果全部进入人工复核。

### 4.6 旧目录优先与新目录候选

旧有目录是主要分类入口，但不是不可修改的模板。处理顺序固定为：

1. 先完整读取当前专题既有 `【大题】` 下的三级、四级目录和知识点编号。
2. 检查题目能否唯一、合理地落入既有目录。
3. 既有目录标题不准确但语义边界仍成立时，优先提出改名，不重复新建同义目录。
4. 两个旧目录无法形成稳定边界时，提出合并或重构候选。
5. 只有题目的首要对象不同，才提出新三级目录。
6. 只有同一首要对象下出现独立、稳定的主问或决定性条件，才提出新四级目录。
7. 所有新增、改名、移动、合并、拆分和删除都进入旧—新目录映射表。

### 4.7 新目录数量门槛

数量按去重后的稳定题目身份统计。同题异图、重复来源或多次抓取只计一题。统计范围包括当前分页、当前专题其他分页、已有本地题目清单和可确认的历史专题记录，不能只看当前屏幕。

初版采用以下可配置门槛：

| 去重题量 | 默认处理 | 允许例外 |
|---:|---|---|
| 1 题 | 不创建新目录；优先归入语义兼容的既有目录，否则标记“新题型候选待观察” | 不因单题破例 |
| 2 题 | 默认不创建；继续归入兼容目录或待观察 | 全国旧目录已有稳定类别，或存在明确、独立的教师检索需求，并且边界审核通过 |
| 3 题及以上 | 可以进入新目录候选审核 | 仍须通过互斥、唯一命中、长期检索价值和知识点编号兼容性检查 |

`3 题` 是进入候选审核的默认下限，不等于自动批准。若这些题仅是答案形式不同、常规步骤不同或同一道母题的轻微改编，仍应合并到既有目录。反过来，不能为了满足数量门槛，把本质不同的题硬合并。

### 4.8 Excel 同步和 `SF` 知识点编号

已核对当前目录工作簿：`【大题】` 二级行是容器行，E 列为空；当前 `SF` 编号出现在四级目录行。完整项目按以下层级写入：

| 新目录层级 | Excel 写入 | E 列知识点编号 |
|---|---|---|
| 二级 `【大题】` | B 列写 `【大题】`，并按 Skill 校验插入位置 | 留空；该行是容器，不伪造知识点编号 |
| 三级，有四级子目录 | C 列写三级标题 | 留空，由四级叶子目录承载编号 |
| 三级，直接承载题目 | C 列写三级标题 | 使用新增类别 `SF` 编号；以后若统一细分四级，必须先执行完整承接重构 |
| 四级 | D 列写 `考法N：标题` | 使用新增类别 `SF` 编号 |

新增类别编号格式固定为：

```text
ZCSQG<YYYYMMDD>SF<NN>
```

- `SF` 必须大写，位于日期和序号之间，作为新增分类实体的标记段。
- `NN` 至少两位；编号前扫描同目录全部已确认工作簿，只统计完全匹配该格式的当日编号。
- 同日从最大序号继续，禁止重复和回收。
- 改名或移动但语义实体不变时沿用原编号。
- 拆分时由最接近原语义的延续项保留原编号，其余新实体分配新 `SF` 编号。
- 合并时由最终保留的语义实体沿用编号，其余编号退役。
- 二级 `【大题】` 行只填写 B 列；K 列到最后使用列保持为空，尤其不得生成 P、Q、R 等上传字段。
- 新建三级、四级行不得自行生成 P、Q、R 等系统字段。

## 7. 详细实施步骤

### 步骤 0：建立基线和样本集

**输入**

- 当前题湖题库页面。
- 已有的中考数学目录表和分类规则。
- 至少 3 个专题的大题样本，覆盖纯文字、复杂公式、图形题、跨专题题。

**工作内容**

1. 保存页面结构的脱敏最小样本，只保留实现解析所需字段。
2. 为每个样本记录题目 ID、稳定编号、目录 ID、题干字段是否存在、图片是否存在。
3. 人工制作一批标准答案分类，作为分类效果基线。
4. 样本中不得包含登录令牌、Cookie、CSRF 字段或个人信息。

**产物**

- 脱敏页面解析 fixture。
- 人工确认的分类验证集。
- 页面选择器和字段清单。

**完成条件**

- 样本覆盖主要题型和异常路径。
- 能用题目 ID 唯一关联原题和人工分类。

### 步骤 1：定义分类目录数据格式

**工作内容**

1. 将既有目录转换为受版本管理的 YAML 或 JSON。
2. 为每个节点定义稳定 ID、显示名称、层级、父节点和排序。
3. 记录三级目录是否已有知识点 ID，作为四级目录保护条件。
4. 为容易混淆的相邻目录补充包含条件和排除条件。
5. 设置 `taxonomy_version`，目录变化后必须递增。
6. 从 `math-exam-directory-curation` Skill 生成 `classification-rules.yaml`，记录来源路径、SHA-256、同步时间和 `rule_version`。
7. 将 Skill 中适用于网页分类的自然语言规则拆为两类：模型判断规则和程序可验证规则。
8. 生成同步差异报告；规则发生语义变化时必须人工审核，不允许脚本静默覆盖现有规则包。

**目录节点示例**

```yaml
taxonomy_version: "2026-09-09.1"
rule_version: "math-exam-directory-curation-2026-09-09.1"
topics:
  - id: topic-01
    title: "专题一 实数"
    order: 1
    level2:
      - id: topic-01-large
        title: "【大题】"
        level3:
          - id: real-number-application
            title: "实数的应用"
            knowledge_point_id: null
            include_when:
              - "核心求解依赖实数运算并服务于实际数量关系"
            exclude_when:
              - "核心依赖后续函数、几何或统计知识"
```

**验证**

- 节点 ID 全局唯一。
- 每个非根节点都有有效父节点。
- 同一父节点下名称不重复。
- 目录层级不超过四级。
- 组卷篮配置引用的目录全部存在。
- 规则包记录的 Skill 来源文件哈希与同步报告一致。
- 每条强制复核规则均能映射到校验器代码或页面审核项。

### 步骤 2：实现题湖页面适配器

**工作内容**

1. 集中定义题卡、属性按钮、图片和组卷篮按钮选择器。
2. 从题卡读取：
   - `exercise_id`
   - 稳定题目编号
   - 来源、年份、难度
   - 当前页面 URL 和目录 ID
   - 问题、答案图片 URL
   - 网站已有知识点分组文本
3. 调用同源属性接口，只解析白名单字段：
   - `question_press`
   - `answer_press`
   - `question_text`
   - `question_latex`
   - `answer_latex`
4. 明确忽略令牌、用户字段和其他无关表单数据。
5. 以 3 个并发任务采集，遇到 429 或临时服务错误时有限重试。
6. 用 `AbortController` 支持停止任务和页面切换取消。
7. 页面结构不匹配时立即停止采集并显示“页面结构可能已更新”。

**输出数据**

```json
{
  "exercise_id": "2529221",
  "stable_code": "CS...",
  "catalogue_id": "760593307",
  "source": "...",
  "year": 2025,
  "difficulty": "...",
  "question_press": "...",
  "answer_press": "...",
  "question_image_url": "https://media.wulouai.com/...png",
  "answer_image_url": "https://media.wulouai.com/...png"
}
```

**完成条件**

- 当前一页全部题目均能建立唯一记录。
- 单题失败不阻断其他题目。
- 页面令牌不会进入日志、缓存或导出文件。

### 步骤 3：实现方正书版文本标准化

**工作内容**

1. 保留原始文本 `raw_text`，标准化结果另存为 `normalized_text`。
2. 统一全角、半角、不可见空格和重复换行。
3. 解析常见方正书版分式、根式、上下标和括号标记。
4. 无法可靠转换的片段保留原文，并设置 `normalization_warnings`。
5. 检测下列图片兜底条件：
   - 题干文本为空或明显过短；
   - 未解析控制标记比例过高；
   - 题目包含几何图、函数图像、表格；
   - 仅凭文本出现多个等价候选分类。

**完成条件**

- 标准化不能删除数字、运算符和关键条件。
- 所有转换规则都有包含原文和期望结果的测试。

### 步骤 4：搭建本地服务 `127.0.0.1:3232`

**服务约束**

- 默认绑定 `127.0.0.1`，禁止监听 `0.0.0.0`。
- 默认端口固定为 `3232`，允许通过本地配置覆盖，但油猴脚本默认只连接 `3232`。
- 启动时检查端口占用、目录文件和缓存数据库。
- 服务仅绑定 `127.0.0.1`，不使用额外访问令牌。
- 日志不记录完整题干、答案或模型密钥。

**接口设计**

```text
GET  /health
GET  /api/v1/config
GET  /api/v1/taxonomy?topic_id=<id>&level2_id=<id>
POST /api/v1/classify
POST /api/v1/classify/batch
POST /api/v1/validate
GET  /api/v1/results/<exercise_id>
GET  /api/v1/directory-proposals
POST /api/v1/directory-proposals/audit
POST /api/v1/excel/preview
```

`GET /health` 示例：

```json
{
  "status": "ok",
  "service": "wulou-question-curation-assistant",
  "port": 3232,
  "taxonomy_version": "2026-09-09.1",
  "rule_version": "math-exam-directory-curation-2026-09-09.1"
}
```

**错误约定**

| HTTP 状态 | 场景 | 油猴脚本行为 |
|---:|---|---|
| 400 | 输入字段缺失或格式错误 | 标记单题失败 |
| 409 | 目录版本不一致 | 刷新目录后重新分类 |
| 422 | 无法得到唯一合法分类 | 进入人工复核 |
| 429 | 分类服务繁忙 | 按 `Retry-After` 等待 |
| 500 | 服务内部异常 | 记录请求 ID，保留其他结果 |

**完成条件**

- 油猴脚本能检测服务是否启动。
- 非本机设备无法访问该服务。
- 分类服务未启动时，页面仍可使用手动组卷篮映射功能。

### 步骤 5：实现分层分类引擎

每道题采用逐步升级策略，避免所有题目都调用图片模型。

模型接入采用整页快速 API、单题严格 API 与云端 Batch API 混合模式，详细依据见 `MODEL_INTEGRATION_RESEARCH.md`。当前页默认每 6 题组成一个实时请求并发处理；每题仍独立输出知识分析、最晚必备专题、目录选择和自审结果。单题严格接口保留三阶段独立审核；整个专题或多页任务导出 JSONL 后走 Batch API。本项目不使用本地模型。

#### 5.1 规则预处理

- 当前页面专题和 `【大题】` 只作为弱提示，不裁剪全局专题候选。
- 整页快速模式在一个分块请求内逐题列出完整必备知识点，按目录顺序选择最晚必备专题，再选择三级或四级目录并完成自审。
- 单题严格模式使用独立审核调用检查遗漏的更晚知识点、同级互斥和“含/不含”语义冲突；两种模式的显式数学信号都须通过本地确定性校验。
- 提取题干中的任务动词、主要对象、条件和结论。
- 利用网站已有知识点分组作为辅助信号，不能直接作为最终分类。
- 检查缓存，题目文本哈希和目录版本未变化时直接复用。

#### 5.2 文本分类

模型输入只包含：

- 标准化后的题干；
- 必要时的答案文本；
- 当前专题的候选目录和判定边界；
- 从 `math-exam-directory-curation` Skill 同步的统一分类规则及其版本。

要求模型返回结构化 JSON，禁止返回目录之外的自由标题。

如果现有目录没有语义兼容项，分类结果保留空目标路径，并写入 `proposal_cluster_id`。只有目录候选模块可以产生新标题候选；候选未通过审核和 Excel 同步前，不能用于组卷篮映射。

#### 5.3 图片兜底

只有出现图片兜底条件时才使用题目图片：

1. 先读取问题图片。
2. 问题图片仍无法判断时，再读取答案文本或答案图片。
3. 保存“为什么升级到图片识别”的原因。

#### 5.4 规则后校验

- 检查目标目录是否存在。
- 检查专题前置知识顺序。
- 检查三级目录和四级目录父子关系。
- 检查知识点 ID 对四级目录的保护规则。
- 检查是否只有一个目标路径。
- 根据冲突、缺失信息和模型置信度决定是否复核。

**分类输出示例**

```json
{
  "exercise_id": "2529221",
  "taxonomy_version": "2026-09-09.1",
  "rule_version": "math-exam-directory-curation-2026-09-09.1",
  "target_topic_id": "topic-01",
  "target_level2_id": "topic-01-large",
  "target_level3_id": "real-number-application",
  "target_level4_id": "real-number-application-quantity",
  "required_knowledge": ["实数运算"],
  "primary_object": "实际数量关系中的实数",
  "main_ask": "求实际问题中的数量",
  "confidence": 0.91,
  "needs_review": false,
  "review_reasons": [],
  "classification_method": "text",
  "reason": "核心求解依赖实数运算，实际背景不改变数学结构"
}
```

### 步骤 6：建立置信度和复核规则

置信度阈值必须通过人工样本校准，初版只定义行为，不预设未经验证的准确率目标。

建议状态：

| 状态 | 条件 | 后续操作 |
|---|---|---|
| 高置信度 | 唯一候选、规则校验通过、信息完整 | 可进入批量确认列表 |
| 中置信度 | 唯一候选但依据不足 | 人工快速查看题干和理由 |
| 低置信度 | 多候选、图片依赖或答案依赖明显 | 必须逐题复核 |
| 冲突 | 跨专题、非法父子关系、目录版本不一致 | 禁止自动入篮 |
| 无结果 | 页面或模型未提供有效信息 | 手动分类 |

无论模型置信度多高，下列情况强制复核：

- 目标专题不是当前专题；
- 同时存在两个以上合法目录；
- 需要新建目录才能容纳；
- 三级目录知识点 ID 状态与四级结果冲突；
- 题干文本与题目图片明显不一致。

### 步骤 7：实现 12 个组卷篮映射

**设计原则**

- 组卷篮是当前分类方案中的槽位。
- 每个槽位映射一个三级目录或一个三级/四级完整路径。
- 第 12 个槽位默认保留为“待人工复核”。
- 映射必须绑定专题、二级目录和目录版本。

**配置示例**

```yaml
profile_id: topic-01-large-a
title: "专题一 实数 · 大题 · 分类组 A"
taxonomy_version: "2026-09-09.1"
slots:
  1:
    target_level3_id: real-number-application
    label: "实数的应用"
  2:
    target_level3_id: real-number-calculation
    target_level4_id: without-rationalization
    label: "综合计算｜无有理化"
  3:
    target_level3_id: real-number-calculation
    target_level4_id: with-rationalization
    label: "综合计算｜含有理化"
  12:
    review_only: true
    label: "待人工复核"
```

**超过 12 个分类时**

1. 优先按三级目录缩小当前范围。
2. 仍超过 11 个有效分类时，拆为分类组 A、B。
3. 切换分类组后，页面重新计算每个建议对应的槽位。
4. 不允许把两个无法区分的最终目录映射到同一槽位。

### 步骤 11：导入导出与人工回退

**导出格式**

- JSON：保留完整结构、置信度、依据和版本信息。
- CSV：用于 Excel 查看和人工统计。
- JSONL：用于云端异步 Batch 分类和中断恢复；每行只放一道题的独立请求。

**导入校验**

- 校验题目 ID、内容哈希和目录版本。
- 目录版本过期时只展示旧结果，不允许直接入篮。
- Skill 规则版本过期时按旧结果展示，但必须重新校验或重新分类后才能入篮。
- 相同题目存在多个结果时保留人工确认结果，其余进入冲突列表。

**服务不可用时**

- 保留页面组卷篮标签映射。
- 允许手动为题目选择目录并加入对应组卷篮。
- 允许导出采集数据，待本地服务恢复后提交云端 Batch 分类并导入结果。

### 步骤 13：真实页面验收

真实页面验收分三轮进行：

1. **只读验收**：采集和分类，不执行入篮。
2. **小批量验收**：选择 5 至 10 道已人工确认题目，逐题入篮并核对网站计数。
3. **整页验收**：处理一页题目，检查失败隔离、重复运行和缓存复用。

验收记录至少包含：

- 页面目录和目录版本；
- 页面题目总数、成功采集数和失败数；
- 自动建议数、人工修改数和待复核数；
- 入篮成功数、失败数和重复跳过数；
- 未解决的问题及其复现条件。

### 步骤 14：新目录审核与 Excel 同步

该步骤只处理已经聚类成组的新题型候选，不由单题分类请求直接触发。

#### 14.1 汇总候选题组

1. 按标准化题干、主对象、主问和决定性条件聚类。
2. 用 `exercise_id` 去重并列出全部来源。
3. 统计当前专题、全部分页和历史清单中的去重题量。
4. 输出每组与现有三级、四级目录的相似项及不能归入的具体原因。
5. 题量不足时归入兼容目录或保持“待观察”，不进入编号阶段。

#### 14.2 对照旧目录

1. 扫描同一目录下全部已确认的 `★全国中考数学-导出目录` 工作簿。
2. 用专题起止锚点提取完整旧目录树，不能假定各版本行号相同。
3. 比较历版标题、层级和知识点编号变化。
4. 形成旧—新映射，处理方式限定为沿用、改名、移动、合并、拆分、新增或删除。
5. 优先复用仍然准确的旧目录；旧目录边界不清时提出修订，并记录理由。

#### 14.3 语义审核

候选目录必须同时通过：

- 三级目录全对全互斥检查；
- 同一三级下四级目录唯一命中检查；
- 标题背景去具体化检查；
- 隐藏原分类结果后的盲分测试；
- 边界题压力测试；
- 题量门槛和独立检索价值检查；
- 父三级 E 列知识点编号兼容性检查；
- 当前纳入题与跨专题移交题的数量守恒检查。

任一检查失败，候选退回修改或继续观察，不分配编号、不生成正式 Excel。

#### 14.4 生成可审核预览

在写入前生成 Markdown 或 HTML 预览，至少展示：

```text
候选类型：新增四级目录
建议位置：专题一 / 【大题】 / 实数的应用
建议标题：考法N：……
去重题量：5
题目 ID：……
与旧目录的差异：……
互斥边界：出现 …… 归本类；出现 …… 归相邻类
编号动作：待确认后分配 ZCSQG<YYYYMMDD>SF<NN>
```

只有使用者确认该具体预览后，才允许进入 Excel 写入。

#### 14.5 写入新 Excel 版本

1. 选择最新确认的基准工作簿并记录 SHA-256，只读打开。
2. 按 `★全国中考数学-导出目录,ID-<ID>-YYYY-MM-DD vN.xlsx` 计算新文件名。
3. 扫描当日全部 `SF` 编号，锁定本次连续序号区间。
4. 先复制为临时输出，所有写入只发生在临时文件。
5. 按 B、C、D、E、N、S 列约定写入新目录、知识点编号、说明和题量。
6. 更新当前专题大题目录分表中的题号—三级—四级—归类依据清单。
7. 重新打开临时文件，验证公式、样式、目录层级、编号唯一性和题量守恒。
8. 对基准工作簿再次计算 SHA-256，确认未改变。
9. 校验全部通过后，将临时文件重命名为新版本；校验失败则保留诊断结果，不交付错误文件。

#### 14.6 发布新目录版本

1. 从新 Excel 版本重新导出 `taxonomy.yaml`。
2. 提升 `taxonomy_version`。
3. 使旧分类缓存进入“需重新校验”状态。
4. 更新受影响的组卷篮映射方案。
5. 对受影响题目重新执行唯一命中校验。

**完成条件**

- 没有单题触发的新目录。
- 所有新增类别均有题量证据、互斥边界、旧—新映射和人工确认记录。
- 新 Excel 可重新打开，基准文件哈希未变。
- 新增类别知识点编号符合大写 `SF` 规则并保持唯一。

## 8. 分阶段交付计划

### 里程碑 A：只读采集器

交付：

- 项目骨架和 README。
- 油猴脚本页面适配器。
- 当前页题目采集。
- JSON 导出。
- 结构变化错误提示。

验收：当前测试页题目 ID 不遗漏、不重复，敏感字段不进入导出。

### 里程碑 B：目录与手动分类界面

交付：

- 目录配置和校验工具。
- 12 个组卷篮方案。
- 折叠面板和题卡分类徽标。
- 手动选择、确认和本地保存。

验收：服务未启动时也能完成手动分类和入篮准备。

### 里程碑 C：本地分类服务

交付：

- `127.0.0.1:3232` 服务。
- 文本标准化。
- 基于 `math-exam-directory-curation` Skill 规则包的文本分类、规则后校验和 SQLite 缓存。
- 单题、批量接口及错误处理。

验收：同一题目重复识别可命中缓存；目录变化后旧缓存自动失效。

### 里程碑 D：图片兜底和人工复核

交付：

- 图片识别升级条件。
- 问题图片和答案图片的分级调用。
- 置信度、分类依据和冲突原因展示。
- 人工修改结果回写缓存。

验收：复杂公式和图形题不会因文本缺失而直接错误归类。

### 里程碑 E：安全批量入篮

交付：

- 批量审核列表。
- 人工确认后的有限并发入篮。
- 成功验证、失败重试和重复保护。
- 操作日志导出。

验收：失败项不影响其他题目；重复执行不会产生无法解释的重复操作。

### 里程碑 F：多页与多专题稳定性

交付：

- 当前目录全部分页处理。
- 目录切换和分类方案自动切换。
- 断点恢复和统计面板。
- 使用说明和故障排查文档。

验收：跨页结果与题目 ID 一一对应，刷新页面后可以恢复审核状态。

### 里程碑 G：目录演进与 Excel 同步

交付：

- 新题型候选聚类和去重题量统计。
- 旧目录全量对照、旧—新映射和语义审核报告。
- 新目录预览与人工确认流程。
- Excel 临时写入、`SF` 编号分配和完整性校验。
- 新目录版本发布和旧缓存失效处理。

验收：基准工作簿未改变；新文件完整可读；新增三级、四级目录及适用的知识点编号同步完成。

## 9. 完成定义

项目达到可日常使用状态，需要同时满足：

- 能稳定读取当前页面题目及属性文本。
- 能连接 `127.0.0.1:3232` 并完成批量分类。
- 每个分类结果包含目录路径、置信度、依据和复核状态。
- 分类输出经过目录存在性、父子关系、专题顺序和唯一性校验。
- 当前分类结果记录 Skill 规则版本；Skill 更新后旧结果不会绕过重新校验。
- 12 个组卷篮显示明确的三级或四级标题。
- 网站写操作全部发生在人工确认之后。
- 缓存可避免未变化题目的重复识别。
- 敏感字段、题库原文缓存和个人截图不被 Git 跟踪。
- 页面结构变化、服务离线、模型异常和单题失败都有明确提示和回退路径。
- 新目录不会由单题自动创建；候选经过数量门槛、旧目录对照、语义审核和人工确认。
- 通过审核的新目录能够写入新的 Excel 版本，并为适用的新增叶子三级或四级实体分配唯一 `SF` 编号。
- Excel 同步不会覆盖基准工作簿，未变区域和公式通过完整性校验。
- README 包含安装、启动、配置、更新和故障排查步骤。

## 10. 实施前需要固定的配置

进入编码阶段前，只需确定以下内容：

1. 第一批要处理的专题及其完整三级、四级目录。
2. 分类目录的当前权威来源文件。
3. `math-exam-directory-curation` Skill 当前规则快照及同步报告。
4. 第一家云模型供应商、具体模型版本及人工标注集的验收阈值；接入模式已固定为“实时 API + 云端 Batch API”，不使用本地模型。
5. 第一个 12 槽组卷篮映射方案。
6. 用于验收的人工标注题目样本。
7. Excel 同步使用的最新确认基准工作簿及其专题边界。

其余页面适配、服务端口、缓存方式、审核流程和界面形态按本文方案执行。
